# CAS-Print — production-ready каркас сайту

Next.js (App Router) + TypeScript + Tailwind CSS. Замовлення й заявки на
власний принт **зберігаються по-справжньому** (Postgres через Prisma) і
надсилають email-сповіщення — це вже не демо, а робочий прийом замовлень,
який лишається розгорнути на хостингу з підтримкою Node.js.

Каталог товарів (назви, ціни, фото) поки що — типізований mock-шар
(`lib/data.ts`), який легко редагувати прямо в коді; переносити його в базу
даних не обов'язково для того, щоб реально отримувати замовлення (див.
розділ «Наступний крок» нижче).

## Що вже працює по-справжньому

- **Checkout** (`app/api/checkout/route.ts`) — перевіряє ціну й наявність на
  сервері, створює `Customer` / `Address` / `Order` / `OrderItem` в Postgres,
  надсилає лист-підтвердження клієнту й лист-сповіщення власнику магазину.
- **Створити свій принт** (`app/api/custom-print-requests/route.ts`) —
  перевіряє тип і розмір файлу, завантажує його у Vercel Blob (файлове
  сховище, не публічна `/public`-папка сайту), зберігає заявку в
  `CustomPrintRequest` і сповіщає власника листом.
- **/admin/orders** — читає реальні замовлення з бази й показує їх списком
  (номер, клієнт, сума, статус, дата).

## Що потрібно зробити, щоб це запрацювало на хостингу

Все нижче — безкоштовні або дуже дешеві сервіси, налаштування займає
20–30 хвилин сумарно.

### 1. Хостинг застосунку — Vercel

Це найпростіший спосіб розгорнути Next.js без власного сервера.

1. Заведіть акаунт на vercel.com, підключіть GitHub (залийте туди цей
   проєкт) або скористайтесь `vercel deploy` з термінала.
2. Vercel сам визначить, що це Next.js, і збере проєкт.

### 2. База даних — Neon (Postgres)

1. Створіть безкоштовний проєкт на neon.tech (або supabase.com — теж
   підійде, це звичайний Postgres).
2. Скопіюйте рядок підключення (`postgresql://...`) у змінну середовища
   `DATABASE_URL` — і локально в `.env`, і в Vercel → Project → Settings →
   Environment Variables.
3. Застосуйте схему: локально — `npx prisma migrate dev --name init`; або
   через Vercel — додайте `npx prisma migrate deploy` у build command, чи
   виконайте це вручну одноразово з вашої машини, вказавши той самий
   `DATABASE_URL`.

### 3. Пошта — Resend

1. Створіть акаунт на resend.com.
2. Підтвердіть домен (наприклад, `cas-print.com.ua`) або скористайтесь їхнім
   тестовим доменом, поки перевіряєте роботу.
3. Створіть API-ключ → `RESEND_API_KEY`.
4. `ORDERS_FROM_EMAIL` — адреса на підтвердженому домені (напр.
   `orders@cas-print.com.ua`).
5. `ORDERS_NOTIFICATION_EMAIL` — куди приходять сповіщення про нові
   замовлення й заявки (пошта власника).

Якщо ці змінні не задані, checkout і заявки все одно працюють і
зберігаються в базу — просто лист не надсилається (це залоговано в
консолі), щоб не блокувати запуск, поки пошта ще не підключена.

### 4. Файлове сховище для «Створити свій принт» — Vercel Blob

1. У Vercel: Project → Storage → Create Database → Blob.
2. Vercel сам додасть змінну `BLOB_READ_WRITE_TOKEN` у production; для
   локальної розробки скопіюйте той самий токен у `.env`.

### 5. Змінні середовища одним списком

Скопіюйте `.env.example` в `.env` і заповніть значеннями з кроків 2–4.
Ті самі значення продублюйте в Vercel → Environment Variables.

## Що поки що НЕ підключено (свідомо, за принципом «не вигадувати дані»)

- **Оплата.** Онлайн-оплата на сайті свідомо не підключена — після
  замовлення менеджер зв'язується з клієнтом у Viber/Telegram/WhatsApp
  (клієнт сам обирає месенджер при оформленні) і узгоджує спосіб оплати:
  повна оплата онлайн, часткова передоплата 50% при накладеному платежі,
  готівка або безготівковий розрахунок (див. `/delivery-and-payment`). Якщо
  згодом знадобиться приймати оплату прямо на сайті — потрібно буде обрати
  провайдера (LiqPay, Fondy тощо) і я підключу.
- **Доставка.** Тільки Нова Пошта, у поштомат — клієнт вказує місто й номер
  поштомата вручну. Реальний автопідбір міста/поштомата через API Нової
  Пошти вимагає їхнього ключа (`NOVA_POSHTA_API_KEY` вже є в `.env.example`).
- **Каталог у базі даних.** Товари й ціни зараз редагуються в
  `lib/data.ts`. Якщо потрібно, щоб адмін міняв каталог через адмінку без
  редагування коду — це наступний, окремий крок (перенесення `Product`/
  `Variant` у Prisma, як уже описано в `prisma/schema.prisma`).
- **Зміна статусу замовлення в адмінці.** Зараз `/admin/orders` — тільки
  перегляд. Кнопки зміни статусу потребують захищеного endpoint із
  автентифікацією адміна (щоб хтось сторонній не міг це робити).

## Швидкий старт (локально)

```bash
npm install
cp .env.example .env   # заповніть хоча б DATABASE_URL
npx prisma migrate dev --name init
npm run dev
```

Відкрити http://localhost:3000. Оформіть тестове замовлення на `/checkout`
і перевірте, що воно зʼявилось на `/admin/orders`.

## Структура проєкту

```
app/
  page.tsx                  — головна
  catalog/                  — каталог з фільтрацією через URL
  product/[slug]/           — сторінка товару
  cart/                     — кошик (localStorage)
  checkout/                 — 4-кроковий checkout → реальне замовлення в БД
  custom-print/             — заявка на власний принт → файл + БД + email
  admin/orders/             — реальний список замовлень із бази
  api/                      — route handlers
lib/
  types.ts, data.ts         — типи й mock-каталог товарів
  prisma.ts                 — Prisma client singleton
  email.ts                  — надсилання листів через Resend
  cart-context.tsx          — кошик гостя на localStorage
prisma/schema.prisma        — повна схема БД (замовлення вже підключені,
                              каталог — на майбутнє)
```
