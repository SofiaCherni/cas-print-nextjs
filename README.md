# CAS-Print — production-ready сайт з адмінкою

Next.js (App Router) + TypeScript + Tailwind CSS + Postgres (Prisma).
Каталог товарів, замовлення й заявки на власний принт — усе живе в базі
даних. Товари додаються й редагуються через `/admin/products`, з
завантаженням фото прямо з форми — без редагування коду.

## Що вже працює по-справжньому

- **Каталог у базі даних.** Товари, варіанти (розмір × фасон × колір),
  ціни — все в Postgres. `/admin/products` → «+ ДОДАТИ ТОВАР» створює товар
  і одразу генерує всі його варіанти (3XL–5XL автоматично +50 ₴).
- **Фото товарів** завантажуються у Vercel Blob прямо з форми додавання
  товару — не потрібно нічого класти в код чи заливати на GitHub.
- **Checkout** — перевіряє ціну й наявність на сервері, зменшує залишок на
  складі, створює замовлення в Postgres, надсилає лист-сповіщення власнику.
- **Створити свій принт** — перевіряє файл, зберігає заявку в базу, сповіщає
  листом.
- **Адмінка захищена паролем** (`ADMIN_PASSWORD`) — без нього ніхто сторонній
  не зможе зайти на `/admin/*`.
- **/admin/products** — список товарів з можливістю приховати/показати чи
  видалити. **/admin/orders** — реальний список замовлень.

## Швидкий старт (локально)

```bash
npm install
cp .env.example .env   # заповніть хоча б DATABASE_URL і ADMIN_PASSWORD
npx prisma migrate dev --name init
npx prisma db seed      # завантажує 8 стартових товарів, щоб каталог не був порожнім
npm run dev
```

Відкрити http://localhost:3000, а адмінку — http://localhost:3000/admin
(попросить пароль з `ADMIN_PASSWORD`).

## Як додати товар з фото (для власника магазину)

1. Зайти на `/admin` → **ТОВАРИ** → **+ ДОДАТИ ТОВАР**.
2. Заповнити назву, опис, категорію, ціну.
3. Обрати фасони й кольори — для кожної комбінації розмір × фасон × колір
   система сама створить окремий варіант товару.
4. Перетягнути фото (можна кілька) — кожне одразу завантажується й показує
   мініатюру.
5. Натиснути «СТВОРИТИ ТОВАР» — товар одразу зʼявляється в каталозі на
   сайті, без переливання коду і без чекання на деплой.

Щоб приховати чи видалити товар — кнопки «Приховати» / «Видалити» просто в
списку `/admin/products`.

## Змінні середовища

Скопіюйте `.env.example` в `.env`. Коротко, що для чого:

| Змінна | Навіщо |
|---|---|
| `ADMIN_PASSWORD` | Пароль для входу в `/admin` |
| `DATABASE_URL` | Підключення до Postgres (neon.tech / supabase.com) |
| `BLOB_READ_WRITE_TOKEN` | Файлове сховище для фото товарів і заявок на свій принт (Vercel → Storage → Blob) |
| `RESEND_API_KEY`, `ORDERS_FROM_EMAIL`, `ORDERS_NOTIFICATION_EMAIL` | Email-сповіщення про нові замовлення (resend.com) |
| `NOVA_POSHTA_API_KEY` | Поки не використовується — заготовка під майбутній автопідбір міста/поштомата |

Ті самі значення потрібно продублювати в Vercel → Project → Settings →
Environment Variables, і задеплоїти ще раз після зміни `DATABASE_URL` чи
структури схеми (`npx prisma migrate deploy` з тим самим `DATABASE_URL`).

## Що поки що НЕ підключено (свідомо, за принципом «не вигадувати дані»)

- **Оплата.** Онлайн-оплата на сайті не підключена — після замовлення
  менеджер зв'язується з клієнтом у Viber/Telegram/WhatsApp і узгоджує
  оплату (див. `/delivery-and-payment`). Якщо знадобиться приймати оплату
  на сайті — потрібно обрати провайдера (LiqPay, Fondy тощо).
- **Доставка.** Тільки Нова Пошта, у поштомат — місто й номер поштомата
  клієнт вводить вручну. Автопідбір через API Нової Пошти потребує їхнього
  ключа (`NOVA_POSHTA_API_KEY`).
- **Зміна статусу замовлення** (позначити «Відправлено» тощо) в адмінці —
  наступний окремий крок.
- **Редагування вже створеного товару.** Зараз можна тільки створити новий,
  приховати/показати або видалити — форми «редагувати» ще немає.

## Структура проєкту

```
app/
  page.tsx                    — головна
  catalog/                    — каталог із фільтрацією через URL (Postgres)
  product/[slug]/             — сторінка товару (динамічна, без збірки заздалегідь)
  sale/                       — SALE (товари з позначкою onSale)
  cart/, checkout/            — кошик і оформлення замовлення
  custom-print/               — заявка на власний принт → файл + БД + email
  admin/
    login/                    — вхід у адмінку
    products/, products/new/  — список і форма додавання товару
    orders/                   — реальний список замовлень
  api/
    admin/                    — створення/видалення товарів, завантаження фото, логін
    cart/resolve/             — рахує ціну кошика на сервері (клієнт цін не зберігає)
    checkout/                 — створення замовлення
lib/
  types.ts                    — типи застосунку (не змінюються під конкретну БД)
  catalog-constants.ts        — чисті константи/хелpери без Prisma (безпечно для браузера)
  data.ts                     — усі запити до бази (Prisma), тримає ту саму форму, що й типи
  db-mappers.ts                — перетворення рядків з БД у типи застосунку
  prisma.ts                   — Prisma client singleton
  cart-context.tsx            — кошик гостя на localStorage, ціни резолвляться з сервера
middleware.ts                 — пароль-гейт для /admin і /api/admin
prisma/
  schema.prisma                — повна схема БД
  seed.ts                       — стартові 8 товарів (запускається один раз)
```
